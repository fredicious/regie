### `next_step` (`flow.rs`)

1. Cancelled: `ClosePr` if close_pr && PR open && not yet closed by Régie, else `cleanup()` (Cleanup or Nothing if cleaned).
2. PR merged: cleanup.
3. A run is active (`state.active_run`): `Nothing`.
4. `setup_ok == Some(false)`: `AwaitHuman(SetupFailed)`.
5. Last run did not finish: `Crashed` -> `AwaitHuman(RunCrashed)`; `Stopped` -> `AwaitHuman(AgentStopped)`; `Interrupted|Paused|LimitHit` -> restart by last run's role (R11): Builder -> `StartRun{Builder, Resume, original input if it never attached else Resume{note: RESUME_NOTE}}`; Reviewer -> `Review{round}`; Verify -> `Verify{findings}`.
6. Pending message and builder already started: `StartRun{Builder, Message, Message{text}}`.
7. `last_builder_status == Question`: `AwaitHuman(BuilderQuestion)`.
8. No builder run yet: `StartRun{Builder, Initial, Initial}`.
9. `review_step(task, settings.loops.review_rounds)` (`flow.rs:261`): no review -> Review round 1; latest `fix_done && round < rounds` -> next Review round; `Unparsed` -> `AwaitHuman(ReviewUnparsed)`; unruled with a blocking finding -> `AwaitRuling{round}` (unruled with no blocking -> review closed); ruled with no `Fix` -> closed; `Fix` and not fix_done -> `StartRun{Builder, Fix, Fix{findings}}`; fix_done and no verify -> `StartRun{Verify, Verify, Verify{findings}}`; verify passes (`verified`) -> closed; else `AwaitHuman(VerifyFailed)`.
10. `!open_pr_requested`: `StartRun{Builder, OpenPr, OpenPr}`.
11. `pr_missing`: `AwaitHuman(PrNotFound)`; PR not open: Closed -> `AwaitHuman(PrClosed)`, else `Nothing`.

`RunCtl { task, role, input: PromptInput, control: mpsc::Sender<AgentControl>, awaiting: usize }` (:15). `Engine::on_agent(run, event)` (:26; ignores unknown runs): `Spawned{pid}` -> `RunSpawned`; `Attached{native_session,pid}` -> `RunAttached`; `Output(line)` -> confirms queued messages (`MessageDelivered` per awaiting, unless line starts with `MESSAGE_NOT_DELIVERED`), sets `live.last_output[task]`, `bus.publish(BusMsg::Output{task, run, line})`; `Reading` -> `UsageReading` (Claude, no task); `Usage{..}` -> `RunUsage`; `Finished{final_message, outcome, limit_resets_at}` -> removes `RunCtl`, `live.active`, emits `RunFinished`; if outcome `Finished`: Reviewer -> `ReviewReported{round, outcome: parse_review(text)}` (round from `ctl.input` Review), Verify -> `VerifyReported{parse_verify}`, Builder -> `after_builder` (:162: OpenPr -> `poll_now(task, true, false)`; CiFix/ConflictFix -> `poll_now(task, false, true)`); if `limit_resets_at` emits `LimitHit`. Actors on these events: `Actor::Run(run)`.

### Poll loop (`poll.rs`)
`Engine::on_tick` (:56, called from `Input::Tick`): every 30 s (`EVERY_MS`) for each `watched(t)` task (worktree, not cleaned/cancelled/merged, PR requested or open) sends a poll; missing-PR check looks every 10 s x3. `poll_now(id, check, hold)` (:84), `send_poll` (:100, spawns `github.prs_for_branch` + `pr_activity`, replies `Input::Polled`), `on_polled` (:150, emits `PrObserved`, `PrCommentObserved`, `PrMissing`). `Polls::holds(task)` keeps a task's runs waiting after a fix until the look returns. `prune_if_due` daily (`recover.rs:151`).

### recover / shutdown
`pub async fn recover(state: &State, now: Millis) -> Vec<NewEvent>` (`recover.rs:23`): for each run with no outcome, SIGTERM/SIGKILL the agent process group if the pid still looks like the agent, then `RunFinished{Interrupted}` events. Called once in `engine::start`. `pub fn prune_run_files(dir, days, now)` (:126). Shutdown: `EngineHandle::shutdown` / `stop_all_and_shutdown` (see above); `cli::serve_until` calls `stop_all_and_shutdown` then removes server.json.

### Bus (`bus.rs`)

### Auth (`auth.rs`)
`Guard { port, token }`; `new_token()` = 32 random bytes hex. `guard` middleware: Host header must equal `127.0.0.1:<port>` or `localhost:<port>` (else 403 "bad Host"); `GET /?token=<t>` with valid token sets cookie `regie_token=<t>; HttpOnly; SameSite=Strict; Path=/` and redirects to `/`; every request needs the token as `Authorization: Bearer <t>` or cookie `regie_token` (else 401 "missing or wrong token"; constant-time compare); non-GET/HEAD requests with an `Origin` header must be `http://127.0.0.1:<port>` or `http://localhost:<port>` (else 403 "bad Origin"; absent Origin is allowed). An MCP endpoint would pass through this same guard (Bearer token works).

### SSE (`sse.rs`)
`GET /api/events?after=N` (also honours `Last-Event-ID`, takes the max). Subscribes to `engine.bus` first, replays stored events after the id via `Store::open_reader(..).load_after`, then live. SSE event names: `event` (id = event id, data = JSON `Event`) and `output` (data = JSON `{task, run, line}`, no id). On `RecvError::Lagged` it replays from the store. Keepalive 15 s. Everything on the bus that is `BusMsg::Event` is sent; there is no per-session filter.

## 7. Gaps: what does not exist yet

- MCP: no MCP endpoint, route, protocol code, tool registry or MCP-related crate dependency (workspace deps: serde, serde_json, ts-rs, thiserror, rusqlite, anyhow, tempfile, tokio, clap, reqwest, axum, tower, rust-embed, rand, tokio-stream, uuid, libc, async-trait). `ClaudeCli::args` passes no `--mcp-config`, `--strict-mcp-config` (only the probe passes it), `--allowedTools`, `--append-system-prompt` or similar. `RunSpec` has no fields for any of these.
- Lead agent: no lead conversation/session record anywhere (State, events, store); no wake mechanism, wake rules, or scheduler for the lead; `Actor::Lead` is declared but never emitted; no run kind/role for a lead (`Role` is Builder/Reviewer/Verify; every run requires a task and a worktree; `RunStarted` is ignored without `e.task`; `start_run` and `prompt_for` take a `Task`); no lead prompt template; resuming by `--resume <native_session>` exists only for a task's builder (`Task.builder_native_session`); `AwaitRuling` is answered only by `auto_rule`.
- Needs-me queue / items: no `Item`/escalation/confirmation type, event, command, state map, view or route. "Needs me" is only a derived `Flag::NeedsMe(HumanReason)` on a task card from `next_step`; no way to answer or dismiss it other than `MessageAgent`/`RetryTask`/etc.; no confirmations model.
- Chat messages: no lead chat message events, state, view, route or web component. `MessageQueued`/`MessageDelivered` are per-task builder messages only (`Task.pending_messages`). `BusMsg` has only `Event` and `Output` (task-scoped; no task-less output).
- Settings persistence: `Settings` is a plain struct, `Settings::default()` at `serve_command`, copied into `Engine` and `Snapshot` once at `engine::start`; no `SettingsChanged` event, no `Command` to change it, no file, no API route, no web UI, no CLI. No level-to-model map field: `Settings::model_for` is a hard-coded match; `engine::start_run` hard-codes `Provider::Claude`; `Candidate.provider` hard-coded Claude; `TaskCreated.provider` is stored in the log but dropped by `State::apply`; there is no per-task model override.
- Onboarding / project facts: `ProjectFacts` has only `setup, build, test, lint, copy_files, definition_of_done`; there is no onboarding state, flow, event, "facts gathered" marker, free-form notes, or UI. `SetProjectFacts` is set via `regie project set --file` only (no route besides `/api/commands`; facts are readable only inside `State.project_facts`, no GET route for them). `CreateTask` fails with `NoProjectFacts` until facts exist.
- Wake rules: no rule definitions, triggers, debouncing or event-to-wake mapping; the only periodic machinery is the 5 s `Tick` (PR polls every 30 s, daily prune, usage probe).
- Session/project scoping: sessions are created with repos via command; no notion of a lead per session/project; the SSE stream and bus are global (no filter); `GET /api/sessions`, `/api/board`, `/api/tasks/{id}`, `/api/runs/{id}/output` are the only reads (no events list, items, messages, settings, facts or usage-totals endpoints; `RunUsage` totals are in the log only, not in `State`).
- Web: no routing or multiple views; no Lead chat view, no Needs-me panel, no onboarding or settings screens; store has no signals for messages/items/settings/facts; `api/client.ts` has no settings/facts/items/chat calls; `describe.ts` `eventText` has no cases for any new event kind (falls to `words(type)`).
- CLI: no subcommands for lead, items, chat, settings or onboarding; `client.rs` has no methods for them.
- Tests: no fake for an MCP client or a lead; `FakeClaude` scripts are keyed on `RunSpec` only.
